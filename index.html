Tools

This is a collection of tools I have developed for my professional and personal use. Feel free to explore and use them.

Networking

  • Visual IPv6 Network Planning Tool

    Visually split and document IPv6 address space with nibble-aligned boundaries, shareable URLs, and CSV export.

  • IP Address Aggregation Tool

    Aggregate and consolidate IP addresses into CIDR blocks for efficient routing.

  • MAC Address Lookup

    Look up any MAC address or OUI prefix—complete, partial, in any format—or paste CLI output and switch tables to identify vendors in bulk. Longest-prefix matching covers the complete IEEE MA-L, MA-M, MA-S, IAB, and CID registries, flags randomized and virtual-machine addresses, and traces prefix lineage back to previous owners. Every block is browsable by vendor, country, former owner, registry type, and year, and an open MCP endpoint at /mcp resolves one address per call for AI assistants. Everything runs in your browser in 31 languages with no ads or cookies.

icanhazip and whoami inspired tools

The shell command whoami has printed the current user and nothing else for decades, and icanhazip has answered with a single line, your public IP address, since 2010. Both succeed for the same reason. They do one thing. They return a plain value as plain text, so a terminal, a script or a person can read it without looking at a page around it. Nothing is hidden and nothing has to be parsed. That is the whole appeal, and many small services have copied the idea since, each one answering a single question about your connection.

I built these tools after finding that pattern worth copying. Every question a request already knows the answer to has its own address, so 67 hostnames answer with one value each and nothing else. They are robust, because there is very little in them that can break. They are fast, and answer in about the time of a DNS lookup. They cost almost nothing to host, so there is no reason to put a front page, an account or a sign-up in front of them. Add the path whoami to any of them and you get the whole page instead.

ip/whoami map

The whoami page shows the request, location, network, TLS and browser sections, an interactive map, then every request header and the whole request data as JSON. The map host is nothing but the map, filling the whole viewport.

Your IP address

The address the request came from. The version hosts answer only for their own version, so they are empty otherwise.

ip ver ip4 ipv4 v4 ip6 ipv6 v6

Location

Where the network thinks you are. These come from the network, not from a GPS fix, so the city and the postal code can be approximate. The region hosts give the long name, then fall back to the code.

city country co cc countrycode region st state province zip postal zipcode postcode continent timezone tz metro dma eu lat latitude lon longitude geo latlong latlon latlng

Network

The autonomous system and the data centre that answered.

asn as isp org colo edge rtt ray

HTTP and TLS

The protocol and the TLS handshake. JA3 and JA4 are sent only for some requests, and the bot score only where bot management runs.

http proto tls cipher ja3 ja4 bot

Browser

Read straight from the request headers. A shell client sends no Accept-Language, so the language host is empty for most command line use.

ua useragent lang

DNS

These five ask a resolver over the network, so they take longer than the other hosts. The forward check host asks for the PTR record and then tests that it points back at the same address, so it is often empty.

ptr hostname ns nameserver dns

Address block

The allocation from the address registry. This is different data from the ASN hosts. The allocation and the announced prefix can differ, because the announced block is sometimes tighter.

net netname netblock range cidr prefix bgp

Time

The time of the request, in ISO 8601.

utc
